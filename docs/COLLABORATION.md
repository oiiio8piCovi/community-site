# AC社区 协作规范

## 分工

| 目录 | 谁动 |
|------|------|
| `site/` 前端壳（index.html、assets/） | 池棠 |
| `site/api/` | 凉心白日 |
| `site/services/` | 小狄、组长 |
| `site/blog/` | 全员 |
| `docs/` | 组长 |

动别人的目录前，先打招呼。

## 任务流程

讨论需求 → 定需求 → 任务单（GitHub Issue）→ 派发 → 改代码 → PR → 合并

- 任务单带验收标准
- 大改动先讨论再动手

## Git 流程

```bash
git pull                    # 开工前同步最新代码
git checkout -b 功能名      # 新任务开新分支
git add .
git commit -m "板块：干了什么"
git push origin 功能名      # 推分支，然后去 GitHub 提 PR
```

**提交信息格式**：`板块：一句话说明`

- 后端：修复留言列表倒序
- 前端：首页首屏完成
- 插件：新增二维码工具

## PR 描述

提 PR 时，描述框按四条写：

1. 改了什么
2. 为什么改
3. 怎么验证（自测结果或截图）
4. 还有什么没做

例：`后端：留言列表加分页。加 limit 参数。curl 实测返回正常。分页跳页没测。`

## 规矩

1. 每次开工先 `git pull`，避免冲突
2. 提交信息写清楚，别写 "update"
3. 不提交无关文件（`.venv/`、`__pycache__/` 已忽略）
4. 大改动（涉及多人、动结构）先在群里说
5. 文档和代码一起提交。

## 文档要求

- 新成员先读 README → 章程 → 本规范
- 概念级变更（板块、技术栈、路线图）必须同步更新 docs/
- 服务器、部署由组长负责，预览地址发群公告
