# AC社区 协作规范 v1.0

> 状态：生效（2026-08-23）｜ 目标：全组配合不打架

## 一、分工原则

**各人只动自己的板块目录**：

| 目录 | 谁动 |
|------|------|
| `site/` 前端壳（index.html、assets/） | 前端（池棠、凉心白日） |
| `site/api/` | 后端（池棠、凉心白日） |
| `site/services/` | 插件（小狄、组长） |
| `site/blog/` | 全员可写 |
| `docs/` | 组长（文档变更先过一眼再改） |

动别人的目录前，先打招呼。

## 二、Git 流程（全组统一）

```bash
# 开工前先同步最新代码
git pull

# 改完提交（改了什么写清楚，别写"update"）
git add .
git commit -m "板块：干了什么"        # 例：后端：留言接口增加分页参数

# 推上去
git push
```

**提交信息格式**：`板块：一句话说明`。例如：
- `后端：修复留言列表倒序`
- `前端：首页首屏完成`
- `插件：新增二维码工具`

**规矩**：
1. 每次开工先 `git pull`，避免冲突
2. 不要提交无关文件（`.venv/`、`__pycache__/` 已被 .gitignore 忽略）
3. 大改动（涉及多人、动结构）先在群里说，别闷头改
4. README 和 docs/ 是交接文档，改了文档要顺带更新对应部分

## 三、审查

草案阶段不做强制 PR 审查，但**别人的代码先看再合**：
- 新人第一次提交前，组长过一眼
- 发现 bug 直接在群里说，别憋着（Bug 是大家的共同教学素材）

## 四、文档要求

1. 新成员必读：README → PROJECT-PLAN → COLLABORATION
2. 每次"概念级"变更（板块定义、技术栈、路线图）必须同步更新 docs/
3. 文档和代码一起提交，禁止"代码改了文档还停在三个月前"

## 五、环境与权限

- 服务器、域名、部署由维护板块（组长）负责
- 部署发布流程上线前，不要自己往服务器上乱放文件
- 演示站：`http://192.168.1.13:18080/`（内网，仅限看效果）
